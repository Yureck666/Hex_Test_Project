# Техническое задание: Hexagon Chain Reaction

## Общее описание
Головоломка где игрок расставляет стопки шестиугольников на hexagon grid поле, запуская цепные реакции складывания. Когда верхние шестиугольники соседних стопок совпадают по цвету, они перелетают с высокой стопки на низкую. Стопки из 10 элементов исчезают. С каждой исчезнувшей стопкой скорость реакций увеличивается на 30%.

---

## ПОЛЕ И ЯЧЕЙКИ

### Hexagon Grid
**Описание:** Игровое поле состоит из шестиугольных ячеек, расположенных в hexagon grid layout.

**Параметры (настраиваемые):**
- Ширина поля (количество колонок)
- Высота поля (количество рядов)
- Размер одной ячейки
- Зазор между ячейками

**Состояния ячейки:**
1. **Пустая** - доступна для установки стопки
2. **Занятая** - содержит стопку
3. **Недоступная** - не является частью игрового поля

### Визуал пустой ячейки
**Компонент:** Префаб с настраиваемым визуалом

**Требования:**
- Должен содержать конкретный Renderer компонент для подсветки (настраивается в Inspector)
- Цвет/материал основной ячейки настраивается дизайнером
- Форма: правильный шестиугольник

### Подсветка валидной ячейки
**Триггер:** Когда перемещаемая стопка находится над пустой ячейкой

**Визуал:**
- Анимация: плавное появление (fade in/scale up)
- Длительность появления: настраиваемая
- Renderer для подсветки: выбирается в Inspector префаба ячейки
- Цвет/эффект: настраивается дизайнером

**Поведение:**
- При наведении на пустую ячейку → подсветка плавно появляется
- При уходе от ячейки → подсветка плавно исчезает
- При наведении на занятую ячейку → никакой реакции

## СТОПКИ ШЕСТИУГОЛЬНИКОВ

### Структура стопки
**Описание:** Стопка состоит из шестиугольных элементов, расположенных вертикально друг над другом.

**Визуал:**
- Шестиугольники расположены ровно друг над другом (без смещения/поворота)
- Между шестиугольниками есть небольшой зазор
- Размер зазора: настраиваемый

### Цвета шестиугольников
**Доступные цвета:** 7 штук
1. Белый
2. Синий
3. Голубой
4. Желтый
5. Красный
6. Фиолетовый
7. Зеленый

**Примечание:** Конкретные цветовые значения (hex/RGB) настраиваются дизайнером в материалах.

### Стопки на поле (начальное состояние)
**Данные:** Задаются в ScriptableObject уровня

**Настраиваемые параметры:**
- Позиция каждой стопки (координаты на grid)
- Высота каждой стопки (количество шестиугольников)
- Последовательность цветов снизу вверх для каждой стопки

**Поведение:** При старте уровня стопки создаются на заданных позициях с заданной конфигурацией.

### Три стопки для выбора
**Расположение:** Внизу экрана, в ряд

**Параметры:**
- Размер: такой же как у стопок на поле
- Высота каждой: настраиваемая в ScriptableObject
- Последовательность цветов: заданная (не случайная) в ScriptableObject
- Порядок появления: фиксированный, заранее определенный

**Поведение:**
- В начале игры видны 3 стопки
- После установки одной стопки на поле → место остается пустым (новая НЕ появляется)
- Можно взять только еще не использованные стопки

## DRAG & DROP МЕХАНИКА

### Взятие стопки
**Триггер:** Tap/Click на одну из трех стопок внизу экрана

**Визуал:**
- Стопка плавно поднимается вверх
- Высота подъема: настраиваемая
- Длительность анимации подъема: настраиваемая (по умолчанию 0.5с)
- Easing: настраиваемый (рекомендуется ease-out)

**Технически:**
- Создается тень под поднятой стопкой
- Стопка переходит в режим следования за курсором/пальцем

**Ограничения:**
- Нельзя взять стопку, которая уже стоит на поле
- Нельзя взять пустое место (если стопка уже использована)

### Перемещение стопки
**Поведение:** Стопка следует за позицией курсора/пальца

**Технически:**
- Используется lerp для плавного движения (не мгновенное)
- Скорость lerp: настраиваемая
- Стопка остается на фиксированной высоте над полем
- Тень всегда отображается под стопкой

**Визуал:**
- Без изменения масштаба
- Без изменения прозрачности
- Без дополнительных эффектов

### Валидация места установки
**Когда проверяется:** Постоянно во время перемещения

**Правила:**
- Валидная ячейка = пустая ячейка на игровом поле
- Невалидная = занятая ячейка или вне поля

**Визуальная обратная связь:**
- Валидная ячейка → подсветка (см. раздел "Подсветка валидной ячейки")
- Невалидная → никакой подсветки

### Отпускание - успешная установка
**Условие:** Отпустить стопку над пустой ячейкой

**Анимация:**
- Стопка плавно опускается на ячейку
- Длительность опускания: настраиваемая (по умолчанию 0.5с)
- Easing: настраиваемый
- Тень исчезает

**Технически:**
- Стопка фиксируется в центре ячейки
- Запускается проверка условий для цепной реакции
- Стопка становится частью игрового поля

**Звук:** Нет

### Отпускание - неуспешная установка
**Условие:** Отпустить стопку НЕ над пустой ячейкой (вне поля или над занятой)

**Поведение:**
- Стопка возвращается на исходную позицию (в место выбора внизу)
- Движение: плавное, с фиксированной скоростью
- Скорость возврата: настраиваемая (не время, а units per second)
- Траектория: по прямой

**Визуал:**
- Никаких дополнительных эффектов
- Тень остается

**Технически:**
- Стопка снова становится доступной для взятия
- Позиция в списке трех стопок восстанавливается

**Звук:** Нет

## ЦЕПНАЯ РЕАКЦИЯ

### Условие запуска реакции
**Триггер:** Стопка успешно установлена на поле

**Проверка:**
1. Получить верхний шестиугольник установленной стопки
2. Получить все соседние ячейки (6 направлений в hexagon grid)
3. Для каждой соседней ячейки, если там есть стопка:
   - Проверить цвет её верхнего шестиугольника
   - Если цвет совпадает → добавить в список для реакции

**Результат:**
- Если найдены совпадения → запускается перелет шестиугольников
- Если совпадений нет → ничего не происходит, ожидается следующий ход игрока

### Логика перелета
**Правило:** Шестиугольники перелетают с высокой стопки на низкую

**Алгоритм:**
1. Собрать все стопки с одинаковым верхним цветом (включая только что установленную)
2. Определить самую высокую стопку (если несколько одинаковых по высоте → выбрать любую)
3. Целевая стопка = любая другая стопка из группы (самая низкая или любая)
4. Все верхние шестиугольники совпадающего цвета перелетают с самой высокой стопки на целевую

**Последовательность перелета:**
- Шестиугольники стартуют по очереди
- Задержка между стартами: настраиваемая (по умолчанию 0.1с)
- Первыми летят шестиугольники с самой высокой стопки

### Анимация перелета одного шестиугольника
**Движение:**
- Траектория: по дуге (arc)
- Высота дуги: настраиваемая
- Длительность полета: настраиваемая

**Rotation:**
- Шестиугольник вращается вокруг горизонтальной оси
- Ось вращения перпендикулярна направлению полета
- Угол: 180° (один переворот)
- Вращение синхронизировано с полетом (заканчивается вместе с прилетом)

**Технически:**
- Шестиугольник удаляется из исходной стопки в момент старта
- Добавляется в целевую стопку в момент прилета

**Звук:** Нет

### Приземление шестиугольника
**Поведение:**
- Шестиугольник приземляется на верх целевой стопки
- Без bounce эффекта
- Мгновенное фиксирование в позиции

### Повторная проверка
**Триггер:** Все шестиугольники из текущей итерации завершили полет

**Действие:**
1. Снова проверить все стопки на поле
2. Найти группы с одинаковым верхним цветом
3. Если найдены → запустить следующую итерацию перелета
4. Если не найдены → проверить условие исчезновения стопок

**Цикл:** Продолжается до тех пор, пока не останется стопок с одинаковыми верхушками

### Параллельные реакции
**Правило:** Если несколько независимых групп могут реагировать одновременно → они реагируют параллельно

**Условие независимости:** Стопки не участвуют в одной цепи перелета

**Пример:**
- Группа синих стопок на одной стороне поля
- Группа красных стопок на другой стороне
- Обе группы реагируют одновременно

## ИСЧЕЗНОВЕНИЕ СТОПКИ

### Условие
**Триггер:** Стопка достигла высоты 10 шестиугольников

**Проверка:** После каждой итерации перелета

### Анимация исчезновения
**Последовательность:** Сверху вниз (от верхнего шестиугольника к нижнему)

**Для каждого шестиугольника:**
- Анимация: уменьшение scale от 1 до 0
- Длительность: настраиваемая (по умолчанию 0.25с)
- Easing: настраиваемый
- Только scale, без rotation и fade

**Задержка между элементами:**
- Следующий шестиугольник начинает уменьшаться до того как предыдущий закончил
- Задержка старта: настраиваемая (по умолчанию 0.1с)
- Таким образом анимации "заходят друг на друга"

**Пример тайминга:**
- Шестиугольник 1: старт 0.0с, конец 0.25с
- Шестиугольник 2: старт 0.1с, конец 0.35с
- Шестиугольник 3: старт 0.2с, конец 0.45с
- И так далее

### Партиклы
**Триггер:** Последний (нижний) шестиугольник стопки завершил исчезновение

**Визуал:**
- Партикл система настраивается дизайнером
- Цвет партиклов: цвет исчезнувшей стопки
- Позиция: центр ячейки где была стопка

**Технически:**
- Префаб партикла должен принимать цвет через параметр
- Play once and destroy

**Звук:** Нет

### Результат
**После исчезновения:**
- Ячейка становится пустой
- Снова доступна для установки новой стопки
- Увеличивается счетчик исчезнувших стопок (для ускорения)

### Множественные исчезновения
**Если несколько стопок достигли 10 одновременно:**
- Все исчезают параллельно
- Партиклы проигрываются для каждой стопки

## СИСТЕМА УСКОРЕНИЯ

### Множитель скорости
**Формула:** `speedMultiplier = 1.0 + (исчезнувшие_стопки * 0.3)`

**Пример:**
- 0 исчезнувших → 1.0x (нормальная скорость)
- 1 исчезнувшая → 1.3x
- 2 исчезнувшие → 1.6x
- 3 исчезнувшие → 1.9x

**Что ускоряется:**
- Полет шестиугольников (длительность уменьшается)
- Исчезновение шестиугольников (длительность уменьшается)
- Все задержки (пропорционально уменьшаются)

**Технически:**
- Базовые значения времени делятся на speedMultiplier
- Например: `actualDuration = baseDuration / speedMultiplier`

### Сброс множителя
**Триггер:** Игрок устанавливает новую стопку (требуется новый инпут)

**Действие:**
- Счетчик исчезнувших стопок сбрасывается в 0
- speedMultiplier возвращается к 1.0

**Момент сброса:** Когда игрок БЕРЕТ стопку для установки (не когда устанавливает)

**Логика:**
- Цепная реакция от одной установки = одна "волна"
- Между волнами требуется инпут игрока
- Новая волна начинается с нормальной скорости

### Отсутствие лимита
**Примечание:** Нет максимального значения ускорения. Теоретически может ускоряться бесконечно.

## ТУТОРИАЛ

### Условие появления
**Первое появление:** При старте уровня, через 0.5с задержки

**Повторное появление:**
- Если игрок не взял стопку в течение N секунд бездействия
- N = настраиваемое значение (по умолчанию 3с)

### Визуал руки
**Компонент:** Animated sprite или sprite sequence

**Состояния:**
1. **Нормальный** - открытая рука, указывающий жест
2. **Схватил** - закрытая рука/кулак

**Анимация туториала:**
1. Рука появляется (fade in) над правильной стопкой внизу экрана
2. Задержка N1 секунд (настраиваемо)
3. Спрайт меняется на "Схватил"
4. Рука движется к целевой ячейке на поле
5. Задержка N2 секунд (настраиваемо)
6. Спрайт меняется обратно на "Нормальный"
7. Рука телепортируется обратно к стопке
8. Цикл повторяется

**Таргет:**
- Конкретная стопка из трех (настраивается в ScriptableObject уровня)
- Конкретная целевая ячейка (настраивается в ScriptableObject уровня)

### Отключение туториала
**Условие 1:** Игрок взял любую стопку

**Действие:**
- Туториал полностью отключается
- Рука исчезает (fade out)
- Больше не появляется в этой сессии

**Условие 2:** Игрок поставил стопку (неважно правильно или нет)

**Действие:** То же самое - туториал завершается

### Поведение при ошибках
**Если игрок взял неправильную стопку:**
- Туториал всё равно отключается
- Не возвращается

**Если игрок поставил стопку не в ту ячейку:**
- Туториал всё равно отключается
- Не возвращается

**Логика:** Туториал показывается только один раз. Если игрок начал взаимодействие - значит понял механику.

## ПЭКШОТ (PACKSHOT)

### Условие появления
**Триггер:** Игра завершена (условие победы выполнено)

**Задержка:** N секунд после завершения последней реакции (настраиваемо, по умолчанию 2с)

### Анимация появления
**Визуал:**
- Весь пэкшот появляется через fade in
- Длительность: настраиваемая (по умолчанию 1с)
- Easing: настраиваемый

**Фон:**
- Поле с шестиугольниками не важно (будет перекрыто фоном пэкшота)

### Элементы пэкшота
**Компоненты:**
1. Задний фон (sprite/image)
2. Логотип игры (sprite/image)
3. Кнопка "PLAY NOW" (UI button)

**Расположение:** Настраивается дизайнером в UI

**Порядок появления:**
- Все элементы появляются одновременно (вместе с fade in пэкшота)

### Интеграция с Luna
**События Luna:**

1. **При появлении пэкшота:**
```csharp
Luna.Unity.LifeCycle.GameEnded();
```

2. **При любом клике на пэкшот:**
```csharp
Luna.Unity.Playable.InstallFullGame();
```

**Область клика:**
- Весь экран пэкшота кликабелен
- Нет необходимости точно попадать по кнопке
- Любое нажатие → переход в стор

## EDGE CASES И ОГРАНИЧЕНИЯ

### Взаимодействие с полем во время реакции
**Вопрос:** Можно ли взять и поставить новую стопку пока идет цепная реакция?

**Ответ:** Да, можно, если это не мешает текущим реакциям

**Правила:**
- Нельзя поставить стопку в ячейку, которая участвует в текущей реакции
- Можно поставить в любую пустую ячейку, которая не задействована
- Установка новой стопки НЕ прерывает текущую реакцию
- Новая реакция от новой стопки может начаться параллельно, если стопки независимы

### Каскадные реакции
**Вопрос:** Что если текущая реакция создает условия для новой реакции?

**Ответ:** Новая реакция начинается сразу после завершения текущей итерации

**Пример:**
1. Синие шестиугольники перелетают и складываются
2. Одна синяя стопка исчезает (достигла 10)
3. Под ней оказывается красный шестиугольник
4. Красный совпадает с соседом
5. Сразу начинается реакция красных

### Одновременное исчезновение нескольких стопок
**Поведение:**
- Все стопки, достигшие 10, исчезают одновременно
- Анимации исчезновения идут параллельно
- Партиклы проигрываются для каждой стопки
- Счетчик исчезнувших стопок увеличивается на количество одновременно исчезнувших

### Конфликты установки
**Сценарий:** Игрок пытается поставить стопку в ячейку, которая только что стала занятой

**Решение:**
- Валидация происходит в момент отпускания
- Если в момент отпускания ячейка занята → неуспешная установка
- Стопка возвращается обратно

### Нехватка стопок
**Сценарий:** Игрок использовал все 3 стопки, но игра не завершена

**Поведение:**
- Если есть возможность дальнейших реакций (стопки продолжают складываться сами) → ожидаем завершения
- Если реакции остановились → игра завершена (переход к пэкшоту)

## ДАННЫЕ И НАСТРОЙКИ

### ScriptableObject: LevelData
**Описание:** Хранит всю информацию о конкретном уровне

**Поля:**
```csharp
// Grid
int gridWidth
int gridHeight
```

## СЦЕНАРИЙ ПОЛНОГО ПРОХОЖДЕНИЯ

### Шаг 1: Загрузка уровня
1. GameFlowController загружает LevelData
2. GridManager создает hexagon grid
3. Создаются начальные стопки на поле согласно LevelData
4. Создаются 3 стопки для выбора внизу экрана
5. TutorialHand запускает таймер (3с)

### Шаг 2: Туториал
1. Через 3с появляется рука
2. Рука анимируется: показывает стопку → движется к ячейке → возвращается
3. Цикл повторяется пока игрок не возьмет стопку

### Шаг 3: Первая установка
1. Игрок берет одну из трех стопок
2. Туториал отключается
3. Стопка поднимается и следует за курсором
4. Игрок наводит на ячейки → валидные подсвечиваются
5. Игрок отпускает над валидной ячейкой
6. Стопка опускается на место

### Шаг 4: Цепная реакция
1. ReactionSystem проверяет соседей
2. Находит совпадения по цвету верхних шестиугольников
3. Определяет самую высокую стопку в группе
4. Запускает перелет шестиугольников:
   - Шестиугольники по очереди (с задержкой 0.1с)
   - Летят по дуге, переворачиваясь
   - Приземляются на целевую стопку
5. После завершения полета → снова проверка
6. Цикл продолжается пока есть совпадения

### Шаг 5: Исчезновение
1. Одна из стопок достигает высоты 10
2. Запускается анимация исчезновения:
   - Шестиугольники уменьшаются сверху вниз
   - С задержкой 0.1с между каждым
   - Длительность 0.25с на элемент
3. После последнего элемента → партиклы
4. Ячейка становится пустой
5. Счетчик исчезнувших стопок +1
6. Множитель скорости становится 1.3x
7. Снова проверка условий реакции (с учетом ускорения)

### Шаг 6: Вторая установка
1. Игрок берет вторую стопку
2. Множитель скорости сбрасывается в 1.0x
3. Установка → новая цепная реакция
4. Реакция может идти быстрее (если стопки исчезали)

### Шаг 7: Завершение игры
1. Все стопки исчезли ИЛИ все 3 стопки использованы
2. Задержка 2с
3. Пэкшот появляется (fade in 1с)
4. Вызов Luna.Unity.LifeCycle.GameEnded()
5. Игрок кликает в любом месте
6. Вызов Luna.Unity.Playable.InstallFullGame()
